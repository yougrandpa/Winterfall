## 本轮发现并补齐的缺口

| 环节 | 原有缺口 | 本轮完成 |
| --- | --- | --- |
| 组队准备 | 未装备但有真实库存可领的队员无法入队；组队未核对共享库存总量 | 招募按猎人、装备适配、路径、技能、ID 排序；最多三人的装配组合先校验库存，显式名单仍整体拒绝，不替换成员 |
| 武器与箭 | 集结补给可能空等；首名弓手可能拿走其他队员最后一支箭 | 从背包或公共库存装备真实武器，为其他弓手留出最低箭量；补给缺失或不可达立即退出准备，沿用生产链 |
| 集结与追猎 | 返回集结点的分支可能绕过三十 tick 上限；失去目击后撤退又在同次更新重新预留目标 | 全阶段检查期限，撤退后保持释放；自主招募失败也进入六十 tick 冷却 |
| 驱赶与截击 | 两人围鹿缺少明确截击角色；侧翼仍可能从后方直接开弓 | 两人鹿队分出侧翼，优先前往最后目击运动方向前方的可达工作格；分配不同工作格、避免占位并在必要时绕行；射位暂时被队友占用时等待或换位，不能误判为接近不可达 |
| 动态求生 | 狼群承受能力只在组队时检查；退路未持续检查；疲惫或有紧急需求的矛手仍可能掩护攻击 | 每 tick 按队员实际可感知的狼群复查风险与退路，武器失效或箭耗尽停止追猎；仅健康、有体力且无紧急需求的矛手短时掩护 |
| 冲锋躲避 | 已经拉弓的猎人不会进入移动分支，可能站着承受冲锋 | 可见冲锋预警优先于攻击，取消尚未释放的攻击并侧移一格，检查两侧障碍和占位；不读取隐藏冲锋者的位置 |
| 遮挡信息 | 受击直接读取攻击者位置；瞄准朝向可能跟随隐藏目标 | 动物只记住已感知位置或箭的来向，攻击者死亡仍可触发逃跑；弓使用最后可见信息作最多两格的有限预判，不读取隐藏目标的新位置 |
| 回收与中断 | 回收者交接的短暂空档可能被其他 NPC 抢占；离队者的未释放攻击可能继续 | 原任务持有尸体回收权限，其他规划器跳过；离队统一取消尚未释放攻击，已离弦弹道保留 |
| 玩家反馈 | 装备候选信息笼统，取消无效任务缺少中文原因 | 显示风险、已装备和待领／待补箭状态；无效取消返回中文原因，成功干预仍按原规则标记辅助成绩 |
| 攻击与画面 | 最后一次阶段帧调整没有新证据；按钮测试有绕过 UI 射线的回退 | 阶段取帧提到纯 C# `CombatAnimation`，覆盖蓄力、出手、冲锋和恢复；移除回退，按钮必须通过实际 EventSystem 射线命中；重新拍摄狩猎画面 |

新增状态均复用既有任务、装备、攻击及冷却字段，无新增权威存档字段。外壳／世界快照 v5、哈希 v7、回放摘要 v6、独立 `saves-hunting-v5` 目录保持不变。未重建 Bootstrap、重置世界配置或修改图集切片。

## 自动狩猎抖动修复（后续反馈）

玩家反馈点击猎物发起自动狩猎后，猎人反复往返，最终显示失败和完成。通过真实 `SimulationEngine.Tick` 与空名单 `RequestHuntCommand` 复现：取箭路上有 NPC 挡路时，位置连续二十 tick 在 `(11,16)` 与 `(12,16)` 间切换，仍停留在集结阶段。根因是移动只临时绕一步，下一 tick 的寻路忽略 NPC 占位，又走回原路；不是正常需求规划反复接管了狩猎。参与者的决策说明还保留着旧采集目标，进一步误导了观察。

- 新增 `HuntingNavigation`，带 NPC 占位及可见冲锋禁行条件规划完整路径，复用已有行动路径和进度，不再每次只躲一步。动态堵路无可行绕路时等待，路通后继续；静态不可达仍退出。集结、领装、回收和返村根据到达范围选择空格，行进途中存读档保持路线及哈希一致。
- 有效且可达的截击格持续使用，失效或目标换向才重新选择；弓手工作格限制在猎物四格射程内，避免侧翼站在五格外反复“截击”却始终无法攻击。
- 标记位置与队伍实际目击分开处理：未目击用 `LastSeenTick = -1`，先前往标记位置，不会在尚未接近时按“失去目击十二 tick”撤退；集结时间不挤占追猎的失联时间。已目击后仍保留十二 tick 的失联限制，整体追猎仍受一百二十 tick 上限约束。快照字段布局保持不变，校验明确接受 `-1` 并拒绝其他非法时刻。
- 接管旧工作时同步当前决策为狩猎，并提供中文原因。正常返村使用 `NpcPlanState.Complete`，不再调用 `Fail("hunt_returned")`；撤退结束保留实际退出原因，动作也不再显示狩猎完成。

## 编辑器完整复验与停止追猎修复

用户随后要求在编辑器完成整轮默认测试，并反馈自动组队后无法点击停止追猎。此次实际使用原工程 Tuanjie **2022.3.62t4**，通过已有 Codely 桥控制原编辑器；没有升级引擎、安装 Pipeline、重建 Bootstrap 或修改世界配置。

首轮完整 EditMode **459 项通过，37.942 秒**。加入同路径按钮回归后，首轮完整 PlayMode **63 项通过、2 项失败，61.464 秒**：一项复现自动安全撤退后停止按钮被禁用，另一项是旧生态快照测试在 800 tick 内尚未产生猎获。

- 停止按钮和 `CancelHuntCommand` 均不再拒绝已经处于自动撤退阶段的任务。玩家停止会结束尚未释放的攻击与剩余掩护期限，重复指令安全；已离弦箭仍按真实弹道结算。既有受伤／需求撤退原因保留，结算锁定仍拒绝普通指令。
- UI 立即防止重复点击，暂停时显示“停止指令待执行 · 恢复或单步后生效”，执行后显示“已停止追猎 · 队员继续安全撤退”；阶段名称改为“撤退回村”，不再笼统显示“狩猎指令已处理”。拒绝反馈限定到本次猎物和发令时刻。
- 默认世界追踪发现撤退者在拥堵位置长期等待，进食、饮水和取暖也被狩猎占用。导航等待现以 `HuntingRules.PathWaitTicks = 8` 为上限，期限复用既有行动字段保存和哈希；急需饮食、休息或取暖的撤退者立即离队，在同 tick 交回既有生存规划。
- 修复后继续观察未改动的默认地图、NPC、装备和天气，首个猎获出现在开局后 **1683 tick**。真实逃脱、补箭、冷却和冬季避寒不能由旧 800 tick 截止条件保证完成。生态快照集成用例保留全部原断言，尤其 `HuntKills > 0`，观察最少 800 tick、最多两个游戏日；存档隔离至临时目录，不通过生成尸体或修改猎物生命值满足该断言。
- 新增 7 项纯代码回归，验证主动停止／已撤退时停止、重复停止、四类紧急生存接管，以及堵路期限存读档一致性。另新增 2 项 PlayMode 回归：受伤自动撤退后通过真实 EventSystem 射线点击停止；未修改默认世界的自动组队／停止在 1×、4×、8× 下执行，暂停入队时哈希保持不变。
