# 架构设计

## 1. 设计目标

- 世界在玩家不操作时持续运行。
- 玩家是观察者和干预者，而不是某个固定角色。
- 世界逻辑不依赖渲染帧率，结果可重复、可观察、可回放。
- 规则系统是权威；LLM 只提供经过校验的高层意图。
- 先做一个垂直切片，再按需求、经济、社会、AI 的顺序扩展。

## 2. 分层

```text
Input / God UI
     │ WorldCommand
     ▼
GameSession / SimulationRunner       (Application)
     │ fixed tick
     ▼
Simulation Engine                    (纯 C#，权威状态)
├─ Core: tick / ids / rng / events / hash
├─ World: map / calendar / factory / resources / crops
├─ Agents: NPC / needs / personality / action
├─ AI: utility decision / bounded plans / decision trace
├─ Navigation: deterministic A*
└─ Systems: updates / commands / state hash
     │ TickResult + read-model DTO
     ▼
Presentation                         (Unity)
├─ Camera / input / selection
├─ Tilemap / sprites / day-night tint
└─ Runtime God View HUD / debug UI

Future LLM Gateway                    (Application，异步)
     ▲ DecisionRequest
     └─ structured IntentProposal → validation → next tick command queue
```

依赖方向：

```text
Presentation ──► App ──► Sim
Editor       ──► App / Presentation / Sim
Tests        ──► Sim / App / Presentation
Sim          ─X─► UnityEngine
```

实现约束：

- `Assets/Game/Scripts/Sim/MyAiWorld.Sim.asmdef` 使用 `noEngineReferences: true`。
- 模拟状态是普通 C# 对象；Unity 只拥有视图、输入、UI、日志和生命周期。
- 运行中的世界变更只能发生在 `SimulationEngine.Tick` 内；工厂建立初始状态，快照解码建立独立候选世界。
- 玩家操作和调试生成 NPC 都通过 `IWorldCommand`，在 tick 边界应用。
- `ScriptableObject` 只保存配置；运行时数据不放在场景组件里。

## 3. 时间与确定性

- 1 tick = 1 游戏分钟。
- 1× 默认 = 2 tick/秒；一天 1440 tick，约 12 分钟现实时间。
- 支持暂停、1×、2×、4×、8× 和单步。
- 不使用 `Time.timeScale` 驱动世界；`SimulationRunner` 用自己的累加器，并限制单帧最多追赶 8 tick。
- 日历为 4 季 × 28 天；起始为春季第 1 天 06:00。
- 模拟状态尽量整数化：坐标、tick、需求值、随机流状态、移动步数。
- 地图生成、NPC 决策和未来系统使用各自的确定性随机流。
- 实体按稳定 `EntityId` 排序迭代，避免依赖 `Dictionary` 顺序。
- `StateHasher` v5 对 tick、地图、RNG、实体位置/行动/路径/需求/性格、库存、资源再生、作物、预留、完整计划和决策元数据，以及信任、社交冷却、有界记忆/时间线做 FNV-1a 哈希。
- 重复回放依赖“种子 + 命令序列 + 记录下来的 LLM 输出”，而不是重新请求模型。

## 4. 世界数据

核心对象：

```text
WorldState
├─ Config (seed / size / tick rate)
├─ Tick
├─ WorldMap (terrain + movement costs)
├─ EntityRegistry (stable ids, sorted NPC list)
├─ Resources (stockpile / renewable nodes / farm plots / reservations)
├─ Ecology (animals / births / bounded population / hunting reservations)
├─ Market (finite stock / treasury / prices / immutable trade ledger)
├─ Materials (initial / produced / consumed per item)
├─ RuntimeRng
└─ NextEntityId

NpcState
├─ EntityId / Identity (name, role, age)
├─ Personality (diligence, caution, sociability, curiosity)
├─ Needs (hunger, thirst, fatigue, health, safety)
├─ Inventory (food / water / seeds, bounded capacity)
├─ Economy (wallet / tool / hunting skill / production counters)
├─ Plan (steps / progress / failure metadata)
├─ Home / Position
├─ RngState
├─ ActionState (idle/move, target, path, step)
├─ Social (directional trust / bounded memories / cooldown)
└─ LastDecision (goal, reason, scores)
```

地图由种子生成：中央村庄、道路、水塘、农田、房屋占位、森林、岩石和水域边界。`House` 与水域/岩石不可通行；农田运行状态保存在 `WorldState.Resources.FarmPlots`，与可通行地形分离。资源节点生成在可达位置。

`Hunger/Thirst/Fatigue` 历史字段均表示满足度（0..10000，越高越好），提供 Food/Water/Energy 别名。需求逐 tick 衰减；进食、饮水、睡眠恢复，长期匮乏影响健康。NPC 背包容量 12，共享库存容量 4000。萝卜种植消耗种子与浇水资源，生长受水分影响，收获产生食物与种子，肥力随耕作/休耕变化。

## 5. 地图与寻路

- 模拟层使用自己的网格；Unity Tilemap 仅是表现。
- 四方向 A*，移动成本：草地/泥土/道路/农田 = 1，森林 = 2，水/岩石/房屋 = 不可通行。
- 稳定 tie-break：先 F 值，再 cell index。
- 寻路在当前 tick 同步完成；NPC 每个行动只规划一次。规模扩大后再做分帧/路径预算。

## 6. 决策与行动

M2 使用 `RuleBasedNpcPolicy` + `SurvivalPlanner`：

1. 根据需求缺口、性格、库存与可执行工作计算目标效用，优先保障生存。
2. 有限领域规划器寻找可达资源，组合移动、取货/采集、食用、睡眠、存放或农事步骤。步骤包含前置条件与效果说明，不执行通用 GOAP 搜索。
3. 计划发布前预留资源数量与工作格；执行时重新校验数量、容量与位置，按稳定 NPC 顺序处理。
4. 紧急需求可中断工作；资源耗尽、不可达或条件变化会记录失败、释放预留并重规划。满包时先卸货；无可行农事时不反复空规划。
5. `SimulationEngine` 在 tick 内应用效果、推进作物/再生和需求。转移与收获先验证全部约束，再一起应用，防止部分执行复制资源。
6. `DecisionTrace` 与计划状态保留目标、原因、分数、失败步骤与恢复信息，供只读观察。

没有生存或生产任务时，NPC 用自己的确定性随机流在短暂休息与附近散步间选择；仓库两格内优先离开柜台。散步目的地校验可达性、占用与资源工作格，并在到达后短暂休息，避免交货后长期原地叠在仓库。紧急需求仍可按原规则中断散步。

预留约束的是资源与工作格；NPC 移动仍可重叠，尚无完整人群避碰。

### M3：生态与经济切片

`EcologyState` 维护独立随机流、稳定顺序动物与出生周期。兔和野猪游荡、逃跑、成对繁殖、自然死亡；每类最多 24 只，4 只保护数量限制狩猎。`Hunt` 计划预留移动猎物，执行器最多追逐 120 分钟，在相邻格检查工具、体力、生命值、容量与保护数量后攻击；受伤与掉落均由 tick 执行。猎物预留在完成、失败和需求中断时释放。

`MarketState` 是有限库存与国库，位置复用村庄库存。`Buy/Sell` 计划保留独立 `UnitPrice` 报价；`TradeCommand` 可排入 tick 边界。立即成交订单校验所有腿后才变更钱包、国库和物品；拒绝也有原因和不可变账本记录，重复 ID 不再结算。价格按库存每小时更新，界限 1..12。公共库存与采集仍提供生存保障；这是混合经济，不是完整付费生存或挂单撮合市场。

`MaterialBalance` 为再生、农业、狩猎计生产，为进食/饮水/播种/浇水计消耗。每种物品按“初始 + 生产 − 消耗 = 当前节点/公共库存/市场/背包总量”核对；国库与钱包合计核对发行总量。新增 NPC 的初始货币计入发行量。动物活体不计为库存物品。

农夫/采集者/猎人的可选工作分别偏向作物、采集与狩猎；需求紧急程度优先。商人偏好饮水供给与余货出售，建造者暂用通用生存工作。实际产出和交易次数进入 NPC 状态，可从检查器核对策略是否真的执行。

哈希 v3 覆盖生态、预留、钱包/工具/技能、计划报价、市场价格/库存/国库/发行量、生产消耗与职业计数。完整不可变账本在追加时更新滚动摘要，摘要和计数进入世界哈希。完整账本也在 `GameSession` 中逐条写入 JSONL，会话头与回放摘要标明哈希版本；回放摘要格式为 v2。

## 7. 表现层

- 2D 俯视，32×32 基础地块与 32 PPU。地形、地物、角色和逐帧动画都在编辑器像素绘制工具中生成，输出为无损 Point 过滤的 PNG 图集 `Assets/Game/Resources/Pastoral/PastoralAtlas.png`；每张切片保留独立命名、锚点与 `.meta`，配置集中在 `PastoralArt.asset`。
- 图集由 **Tools → My AI World → Art → Generate Pastoral Art** 生成。绘制源是 `Assets/Game/Editor/PastoralArtGenerator.cs` 的整数像素指令，不使用 `UnityEngine.Random` 或模拟随机流；视觉变体使用配置中的独立 `visualSeed`。生成流程只写美术资源，不重建 Bootstrap 场景，也不重置世界配置。
- 地图分为四层：`Ground`（地形变体）、`Edges`（道路/泥土/岸线过渡）、`Landmarks`（树、岩石、房屋）和 `Decorations`（花、草簇、碎石）。地物按脚底锚点与 Y 排序，装饰使用较低的固定排序，避免遮挡角色。农田的湿润/干燥状态和作物四个生长阶段使用独立切片；`CropStage.Empty` 不绘制作物。
- 相机从美术配置读取 PPU，以整数倍（1×–6×）缩放并吸附到 1/PPU 像素网格；内部保留未吸附的位置，避免小幅输入丢失。滚轮以鼠标指向处为缩放锚点，跟随模式保持人物居中；档案提供定位和跟随，F 定位、H／右下按钮回村，手动平移、切换人物和读档退出跟随；默认 1920×1080 下保持升级前的世界可视范围。相机仍支持 WASD、右键/中键拖拽和滚轮缩放；像素美术关闭 MSAA/HDR 以避免图集边缘接缝。
- 新增三种屋顶配色的瓦片／花箱小屋、遮棚物资摊位、岸边芦苇与池中睡莲；水面四帧共用模拟动画时钟，暂停冻结。图集共 755 个切片。地物和装饰归属 `WorldGrid`，读档时随地形统一销毁，避免累积旧树和房屋。
- 村民选中使用脚下光环和头顶指针，保留职业服装原色；重叠人物按实际渲染排序选择，排序相同时按实体 ID 稳定选择。
- 人物和动物共享 `CreatureMotion`：按 tick 快照做位置插值，按脚底 Y 计算排序，使用 `SimulationRunner.AnimationTime` 作为统一动画时钟。暂停时时钟冻结，倍速时按世界节奏加速；出生淡入、受伤闪烁和死亡淡出只修改视图颜色与透明度，不写入模拟状态。
- 五种职业通过服装、帽子和工具区分，具有四方向待机/行走帧，以及进食、饮水、睡眠、采集和工作表现。兔有长耳和跳跃帧，野猪有体型、背鬃和奔跑帧；四方向移动帧共用同一套动画时钟，逃跑使用更高步频。
- 人物左右方向使用侧脸、窄身、前后摆腿与摆臂的独立侧身帧。移动动画按视图的实际插值路段播放，最后一格即使模拟行动已结束也会走完；到达后才切为待机或工作。`WorldPresenter.LateUpdate` 在逻辑更新后采样 tick 与插值进度，每个新 tick 都推进插值端点，包括原地停留的 tick，避免旧路段反复回放。
- 冬日 HUD 使用寒地仪表视觉：炭灰底、霜白文字和炉火橙。常驻信息分散在四角，左上显示相对挑战起点的天数、十四道刻痕、时钟与存活人数；右上显示温度、天气和结冰状态；左下显示全局食物、饮水、木材储备及估算时长；右下提供时间控制和导航。1280×720 参考画布下常驻矩形面积约 8.0%，中央区域不放面板或操作引导。
- 点击村民先打开右下 280×124 状态卡，显示姓名、行动、五项需求与异常状态，并提供档案、定位、跟随。主动打开完整档案后，保留概览／关系／计划分页。物资、生态与市场、村庄记事、档案、存档、帮助共用右侧 336 宽的详情区域，互斥展开；打开其他详情保留选择，收起后恢复状态卡。Esc 先收起当前详情，再清除选择。
- UI 在运行时使用 uGUI 构建，以 1280×720 为参考分辨率，通过 CanvasScaler 适配；验收 1280×720、1920×1080 和 2560×1440。主题 `HudTheme` 集中定义冷色表面、文字、暖色重点和危险色；`UiFactory` / `HudLayout` 提供按钮、滚动区、指标行和表格。细边框、小圆角，无厚重阴影；沿用中文字体和 Point 像素图标。
- `GodHud` 保留公开查询与控制接口，协调选择、快捷键、互斥面板、存档回调和反馈；`GodHud.Layout` 构建面板，`GodHud.Binding` 从不可变快照绑定内容。`NpcSummaryOpen` 查询状态卡，`ShowSelectedNpcDetails` 主动展开档案。文本查询包含完整观察数据，与当前分页及折叠状态无关。长姓名在档案内可独立滚动，长原因和全部 32 条记忆保留滚动查看。
- 需求条之外显示名称与百分比；历史曲线与图例沿用需求颜色。资源紧张同时使用文字与橙色短刻度，耗尽使用文字与红色断刻度。全局储备由 `EnvironmentSnapshot` 提供，公共仓库明细留在物资页；供给估算依据默认折叠，避免占据世界视野。关系、计划、市场和日志保留完整数据；守恒误差仅在 F1 调试区显示。
- 存档提供保存、手动读取、自动档、手动备份、自动备份，不存在的文件禁用读取。成功提示四秒后收起，失败提示持续到关闭；完整最近状态保留在存档页。失败读档保留当前世界，成功读档清理旧选择。F5/F9 保留快捷入口。
- 挑战结算使用中央模态界面，优先显示等级、存活人数与冻结储备，详细记录可主动展开。结算仍锁定普通暂停、倍速与单步；继续观察保留二次确认，原始成绩永久冻结。无期限观察不显示挑战刻痕。
- HUD 动效参数集中在 `HudMotion`，全部使用未缩放时间。四角仪表以 60 ms 间隔、180 ms 淡入；`PanelTransition` 支持配置方向、时长、中途反向和即时完成，详情以 180 ms／8 单位右移淡入，人物卡以 140 ms／4 单位下移淡入，关闭 120 ms。重复刷新不重启，关闭立即释放交互、清理提示和完成需求条，互斥切换立即隐藏旧详情。按钮仅移动内部文字／图标，命中矩形固定。
- `GodHud.Motion` 在既有 200 ms 刷新中比较只读快照，分别反馈完成日刻痕、暴风雪／结冰、储备状态、人物异常、种群、迁徙与交易；文字立即更新，需求条在 160 ms 内插值。生态列表以稳定标识保存变化基线，隐藏期间也更新；收起时生态导航提示最多每五秒一次。初始化、世界版本变化与成功读档清理旧反馈，不补播历史。天气的太阳／月亮／雪花使用三层固定图标交叉淡化，中途切换保留当前透明度。
- `HudPulse` 使用独立、无射线的提示线／边框，不覆盖绑定或按钮选中的语义颜色；耗尽储备只轻微调制断刻度的透明度。结算背景 160 ms、成绩卡 220 ms，模态阻挡和挑战锁定立即生效。帮助页的“减少动态”设置通过本机 `PlayerPrefs` 保存；开启后取消位移、循环和分批入场，需求条立即到位，其余淡化不超过 80 ms。常驻容器与装饰不拦截空白区域，操作说明与快捷键保持原规则。
- 随项目打包 Noto Sans SC（SIL Open Font License 1.1，许可文本见 `Assets/Game/Resources/Pastoral/Fonts/OFL.txt`）。F1 面板保留 tick、哈希、日志路径、视图数量与帧率等完整调试信息。
- 昼夜通过全屏色罩表现，不增加逐单位光照。

## 8. 观察、日志与回放

- UI：时间控制、资源总览、可滚动 NPC 检查器（需求、背包、计划条件/效果/失败原因）、最近事件；M3 增加种群/市场面板，展示价格、市场库存、国库、成交/拒绝和最近四笔账本（守恒误差在 F1 调试区），NPC 检查器增加钱包/工具/技能/产出；F1 调试面板默认隐藏。
- App 发布 NPC、资源、作物和事件的不可变快照；表现层不持有可写模拟对象。需求历史每 30 游戏分钟采样，保留最近 24 点并绘制曲线。
- 会话日志：`Application.persistentDataPath/MyAiWorld/sessions/*.jsonl`，记录 session 头、命令、每个领域事件、带双边前后值的结构化交易账本和 session end。
- 回放摘要：`Application.persistentDataPath/MyAiWorld/replays/*.json`，记录种子、世界配置、命令序列、结束 tick 和状态哈希。
- 失败路径：如果日志目录不可写，游戏继续运行并把问题写到 Unity Console，不阻塞模拟。

## 9. LLM 边界（M5 预留）

不会把模型调用写进 tick：

```text
NPC decision window
  → DecisionRequest（只读上下文）
  → LLM 异步调用
  → IntentProposal（严格 JSON schema）
  → 规则校验 + 过期检查
  → 下一 tick 的命令/意图队列
  → 规则系统执行
```

规则：

- 只允许白名单目标与参数，不允许代码、脚本、文件操作或任意命令。
- 规则 AI 永远在线；LLM 超时、限流、非法 JSON、低置信度都回退规则。
- 每个 NPC 有独立人格/记忆/关系；共享一个模型网关，不创建每 NPC 一个模型实例。
- 只在关键决策窗口调用，不是每 tick 调用。
- 记录输入摘要、输出、延迟、Token/成本、回退原因；回放不重新请求模型。
- 默认 `Llm.Enabled = false`，无网络也能完整运行。

## 10. 存档与社会记忆（M4 首版）

- `WorldSnapshot` 位于纯 C# Sim，明确编码权威状态，不依赖反射或 Unity 序列化。快照 v2 支持 v1 无社会数据快照迁移；外壳 v2 支持 v1 校验与迁移。

- `GameSession.Load` 先建立独立候选世界，校验版本、容量、引用、守恒和状态哈希后发布替换。失败保留旧世界；成功递增 `WorldRevision`，Runner 暂停并重置时钟，表现层重建地图与实体，选择/检查器清理旧状态。

## 12. 自主生存扩展（当前规则，取代上文 M2–M4 的对应历史规则）

- `SurvivalWorldState` 持有设施、工地库存、地面物资、遗物与补水状态；`SurvivalNpcState` 持有工具耐久、疾病、生命状态、救援认领与产出计数。物品目录由 `ItemKind.Count` 定义；市场明确仅支持前三类食物、饮用水和萝卜种子，其余物资不可交易。
- `ProductionSystem` 负责确定性选址、原子加工/建设/维护和工具磨损；`WaterSystem` 负责饮水储备、取水批量及蓄水灌溉；`AgricultureSystem` 负责轮作、季节、水分与损伤；`HealthSystem` 负责倒地、救援、转运、照护和死亡；`HuntingSystem` 负责武器射程和视线。执行器只协调这些系统与通用计划步骤。
- 设施只有一个占地格与相邻交互格。选址暂时封闭候选格，验证全部住所、资源和农田仍与仓库连通后发布工地；不使用道路、农田、NPC 当前格或住所邻格。工地与设施库存计入守恒，材料送达后才可施工或加工。工作格与设施认领共同释放；施工进度支持中断续建。
- 默认村庄自主建立净水炉、工作台、蓄水池、水井、灌溉设施各一座。材料来自可再生木材、石料、纤维和草药节点。净水炉每批消耗 6 生水与 1 木材，产出 6 饮用水；井的初始库存为零，每 20 分钟恢复一份，停用设施不可取水。蓄水池不生产水，灌溉每 30 分钟最多消耗一份生水照顾七格内最缺水的未预留作物。
- 饮用水库存低于目标的一半时补充，达到每位存活 NPC 五份时停止；最低目标 20。取水批量根据需求缺口、可达水源路径成本、背包及水桶计算。饮用生水有 35% 的确定性随机患病概率，疾病持续最多 720 分钟，药品可以治疗。
- 萝卜、小麦、豆类生长分别需 720、1440、1000 个有效生长分钟，基础产出分别为 4、8、5 食物和两份对应种子。豆类改善肥力；农夫最多预留并处理四块邻田，优先缺水作物，再收获、播种。夏季耗水翻倍，冬季禁止播种、生长降至四分之一并累积冻害；持续缺水同样累积损伤，达到 1800 枯死。成熟作物停止累积伤害，休耕地恢复肥力。冬季野外食物再生也降至四分之一。
- 猎物包含兔、野猪与鹿，每种上限 24、狩猎保护数 4；自然死亡仍可使种群低于保护数。猎人按路径成本、风险、技能、谨慎程度和产出排序。弓射程四格且校验视线，矛射程一格。攻击与追逐消耗体力，工具耐久归零即计消耗。击杀先生成唯一地面物资，再走到掉落处回收；背包不足或追逐中断保留可回收猎获。
- 健康归零时先进入倒地，绝不先被舒适需求的回血抬回正常状态。180 分钟内可由唯一救援者用一份药品稳定至 1500 健康并转运回家；转运中断后其他人能接手。恢复期卧床，消耗真实食水，其他 NPC 可运送补给；满包时允许直接喂食。健康达到 4000 后恢复工作。超时死亡的背包、工具耐久和钱包进入遗物，死者只保留历史身份与社会记录。
- 新存档外壳/快照为 v3、哈希 v5、回放摘要 v4。新增状态、在途工作、认领和计数进入快照与哈希。旧外壳/快照明确拒绝，新文件使用 `MyAiWorld/saves-survival-v3`，不覆盖旧目录，不迁移旧世界。
- App 发布不可变 `SurvivalReadModel`、设施/地面物资与人物生存状态快照。地图空白选择支持农田、动物、资源、设施与遗物观察；设施状态和生产库存位于物资面板，人物概览显示耐久、疾病和救援窗口。新像素切片追加至原图集，不移动已有切片槽位，不重建 Bootstrap 场景。

## 13. 协作狩猎（2026-10-24，当前规则）

- `WorldState.Hunting` 持有有序狩猎任务及 NPC 重试冷却。`HuntTaskState` 包含队长、猎物、成员与分工、集结点、最后两次目击位置、任务阶段及期限。常规单猎也建立任务；每只猎物、每名 NPC 最多参与一个任务。`ReservedBy` 对应队长或当前回收者，成员权限由任务判定，底层独立战斗仍支持原单人预留。
- `HuntingCoordinator` 在本地生态更新后协调任务，在 NPC 需求与生命状态更新后推进成员行动。阶段为集结、接近、交战、回收、返村和撤退。队伍最多三人，招募路径距离十二格；兔、田鼠、渡鸦和狐狸允许单猎，鹿和野猪至少两人，狼至少三人；野猪和狼需要持矛成员。指定名单整体校验，不能静默删去不可达或不合格队员。
- 集结最多三十 tick，追猎最多一百二十 tick，失去目击十二 tick 后撤退。成员健康低于四千、体力低于二千五百或紧急生存需求触发撤退，失败冷却六十 tick。短时持矛掩护允许队友先走；救援继续由现有药品认领、稳定和转运系统处理。队长退出时按成员稳定顺序接任；中断和倒地统一释放认领。
- `AnimalEncounterSystem` 每 tick 检查本地动物可感知的威胁；日常决策仍为三十 tick，区域居民及代谢仍保留粗粒度节奏。遭遇状态为平静、警觉、逃跑、反击和恢复。短程四步广度搜索选择可达逃生路线，考虑威胁距离、遮蔽、出口和 NPC 占位；脱离感知后只使用最后感知位置。独立奔逃耐力不计入生态生物量，重伤和耐力不足降低逃跑速度。
- 鹿近身受困时踢击；野猪可锁定方向蓄力两 tick，逐 tick 冲锋最多三格，遇墙或接触停止，收招两 tick；同次冲锋只接触一次。狼会响应附近同群成员正在被猎杀或受击的威胁。所有移动先提供箭矢扫掠端点，再结算箭矢和近战接触，防止被箭击杀的野猪随后继续伤人。
- 弓四格范围用于发起攻击；蓄力后猎物跑出发起范围但仍有视线时可以释放，箭离弦后不追踪目标。弓手在发起和释放时都检查真实 NPC 射路，队伍分配不同工作格。误伤继续使用实际弹道和伤害。
- 死亡仍由生态唯一生成尸体并计一次猎获。任务在活体移除后接管尸体，按成员容量顺序回收；实际收获在战斗、倒地和死亡处理后提交。满包换人，剩余物资保留；返村将实际生肉与皮革存入公共库存，随后沿用烹饪链，不直接生成成品食物。
- `RequestHuntCommand` 与 `CancelHuntCommand` 只在 tick 边界执行，待执行命令保存目标及参与者编号；成功的玩家干预将未结算挑战标为辅助成绩。App 发布独立不可变 `HuntingReadModel`，UI 不持有可变任务。
- 动物选择使用实体 ID，右侧生态详情提供风险、分工、自动组队、指定队员和撤退。选中相关任务才显示目标圈、成员图标及冲锋方向。攻击帧按每次攻击的阶段推进，考虑“提交一分钟后发布下一 tick”的时间约定；拉弓、出手、受击和收招不再依赖全局循环帧。暂停冻结，读档不补播历史。
- `HuntingAtlas.png` 追加一百六十四个像素切片。`Generate Hunting Art` 只生成新图集并合并配置；原切片位置和场景配置保留。
- 新存档外壳及世界快照 v5、战斗块 v3、哈希 v7、回放摘要 v6，目录 `MyAiWorld/saves-hunting-v5`。任务、分工、冷却、遭遇耐力和冲锋进度全部进入快照与哈希。旧文件保留并拒绝加载，新规则重新开局。
- 2026-10-25 补齐：`HuntingEquipment` 在任务发布前校验整队的实际装备组合，自动招募按稳定优先级选择能实际装配的队伍；允许从真实库存领装并保留其他弓手的最低箭量，取装与交货可在仓库相邻格进行。`HuntingSafety` 每 tick 检查可感知狼群、健康、武器与退路，并优先处理冲锋侧移；掩护只由健康且无紧急需求的矛手执行。侧翼按最后目击方向选择前方可达工作格；回收交接期间尸体仍归任务。动物受击只获得已感知位置或箭来向，弓按最后可见信息作有界预判；`CombatAnimation` 在 App 纯 C# 层统一阶段取帧。见 [复核记录](Progress/Hunting-Completion-2026-10-25.md)。
- 自动指令稳定性：`HuntingNavigation` 使用带通行谓词的稳定 A*，整段绕开 NPC 和已感知的冲锋预警；行进路径复用既有 `NpcActionState.Path/PathIndex`，继续参与存档和哈希。临时拥堵等待，静态不可达退出；集结、取装、回收、返村可选择各自到达范围内的空格。截击格保持到失效或猎物换向，弓手工作格限制在四格射程内。`LastSeenTick = -1` 表示队伍尚未目击标记猎物，先按标记位置接近；集结不消耗追猎失联时间，首次目击后失联十二 tick 才撤退，追猎总上限仍为一百二十 tick。快照沿用 v5 的字段布局并校验该哨兵值。成功返村使用计划完成状态，撤退保留实际原因，参与者的当前决策同步为狩猎。
- 玩家停止追猎在自动撤退阶段也有效，并立即结束未释放的掩护攻击与掩护期限；已经离弦的弹道继续结算。暂停时显示停止指令待执行，恢复或单步后反馈已停止。导航拥堵等待最多八 tick，复用 `Action.EndTick` 保存期限；撤退成员若急需饮食、休息或取暖，立即离队交回生存规划器，避免狩猎任务长期阻塞求生。

## 14. 野外狩猎准备与耐力（2026-10-25，当前规则）

本节取代上一节中准备、体力、感知及存档版本的对应规则。

- `SurvivalNpcState.Stamina` 是 0..10000 的短期耐力，与需求中的长期 `Energy` 分开。追赶移动消耗 180、普通／潜行移动消耗 20，弓与矛出手分别消耗 600／800。低于 2000 后进入恢复，达到 6000 后退出；恢复每 tick 回复 300，常规轻度活动回复 140，追赶和攻击不回复。常规、潜行与恢复移动间隔分别为一、二、三 tick；零耐力可缓行，不直接触发撤退。精力仍按生存规则衰减和睡眠恢复。
- `HuntingPreparation` 在村庄仓库附近组织最多 90 tick 的准备；任务发布前合计校验真实武器、四支箭／弓手、食物、饮水和必要冬衣。`HuntSupply` 只预留物品，不占仓库工作格；进入追猎、取消、撤退或离队时释放未取用预留。准备进食与休息保证至少六成食水／精力，每人另携带至少一食一水；休息保留额外精力余量以覆盖往返集结点。寒冷条件领穿真实冬衣并评估往返暴露；有冬衣且体温安全的猎人不单因寒夜被日常取暖规则中断。
- 安全停留时可先使用随身食水，消耗进入物资账本；医疗、长期过劳、失温、断粮断水、武器失效、失联和追猎超时仍触发撤退。短期耐力恢复不会被当作导航堵塞。
- 动物危险判断不读取任务与预留。正常接近、潜行接近、受击、短距离声响及真正掠过的箭矢提供感知信息；箭尚未到达时不提前发布近失警报。潜行减少识别距离，不能隐藏相邻接触和受击。狼群依据可感知的战斗响应。猎人只用目击／共享目击与标记位置；丢失视线后先抵达最后位置并搜索已知邻格，不能停在旧标记的弓箭射程外等待。
- 近战仍是 `Hunter` 的长矛分工，主动进入相邻工作格、截击与短时掩护。移动队友可用于规划未来单列路线，但实际下一格始终检查占位，不会跨过或重叠队友；静止障碍保留完整绕行与有限等待。队伍弓手使用有界目击运动预测，潜伏稳定出手获得精度收益；最后一支已离弦箭完成结算后才判断弹药耗尽。
- `CarcassState` 按物品有序记录有限生物产物。兔／狐／狼产毛皮，野猪／鹿产兽皮，渡鸦产羽毛，田鼠主要产少量生肉；覆盖物沿用原体型缩放，成年渡鸦最多两份羽毛。毛皮每份 100 生物量，羽毛每份 25；死亡、腐败、回收与生态转物资均显式记账。尚未回收的产物属于生态，不提前算库存物品。
- 配方 ID 101 使用两毛皮与两纤维制作一冬衣；ID 102 使用一木材、一石料、一羽毛制作六箭。旧配方保留，设施的待加工配方与加工步骤 ID 锁定批次，并进入存档和哈希。
- `HuntTaskState` 保留原始参与者与逐人实际返村位置、时刻。紧急求生可释放行动控制，但任务继续追踪；已完成救援／求生后可继续返村。全部人员返回或伤亡结算后记录有界的最近十六项结果，记录实际入库数量及失败原因；先到者可以恢复日常工作，不要求结算时仍同时站在仓库。仓库满时保留未交物品，不能伪报已入库。
- App 发布独立的耐力／精力、移动模式、补给、尸体产物与结果快照。表现层接入持久尸体及有限掉落，新增 `HuntingFieldAtlas.png` 的 388 个像素切片；用 **Generate Hunting Field Art** 独立生成，不移动旧图集切片或重建 Bootstrap。长矛持械、潜行和缓行使用四方向帧与既有动画时钟。
- 存档外壳和世界快照 v6、生态块 v2、战斗块 v3、哈希 v8、回放摘要 v7，目录 `MyAiWorld/saves-hunting-v6`。旧存档保留并明确拒绝加载，重新开局使用新规则。具体证据见 [本轮验收记录](Progress/Hunting-Field-2026-10-25.md)。

## 15. 冬季保护种植与寒温带生态（2026-10-25，当前规则）

本节替代前文关于作物、冬季繁殖和存档版本的旧规则。冬日挑战仍为十四日；植物生长、孕育时间采用 112 日游戏年的压缩时间，不代表现实农业日历。

- `CropDefinition` 仅有耐寒菠菜、羽衣甘蓝、羊生菜。初始公共种子各 40 份，原有限集市库存为 30 份菠菜种子；不存在冬季采叶返种或制种配方。菠菜／羊生菜最多两次采收，羽衣甘蓝最多三次；每次采收扣肥力，复采重新累计生长、继续耗水。死亡清除植株并留下枯损标记。
- 每个连通农田区域选取最多四个相邻现有地块，固定绑定一个非阻挡的 `FacilityKind.GrowingBed`。外围露地不自动获得覆盖。建材为四木、二石、二纤维，沿用分批实物运输、工作格预留、施工进度与维护；施工完成只扣料一次。维护占用的一份木材不会被炉火抢先烧掉。
- `GrowingBedSystem` 在农业前更新土温、燃料热量与覆雪。完好覆盖减缓散热，石炉每份木材燃烧 720 分钟，热量预算有限，目标土温 10°C；断料逐渐回到环境温度。供暖关闭停止添柴，已经点燃的余火烧完。菜床不改变环境气温和水源结冰，融雪仍使用既有住所有限热量链。
- `AgricultureSystem` 统一播种／浇水前置条件和执行复查。冻土禁播禁浇，低于品种生长温度、无光或缺水停长；覆雪按遮光比例降低有效日照。整数生长余量避免小量光照因舍入消失。超出品种耐受范围积累冻害，成熟植株同样受冻、干旱及露地兽害，不能永久保存。
- 农事先保障住所供暖，随后安排菜床建设／维护、补燃料、清雪，成熟作物优先于浇水和播种；最多四田一批。饮水、急救与村民自身生存沿用上层优先级。种子选择同时考虑方针、土温、种植数量和该工人实际能领取的库存；计划完成前再次检查方针、温度、容量与预留。被打断后的实际收获货物可继续交付仓库或有限集市。
- `FarmFoodDelivered` 只计实际交到公共仓库或集市的直接农业货物，消费和再次买卖不能重复计数。随身未交货标记保存到 NPC 快照并参与哈希；赠食或死亡后转移的货物不追踪原产地，因此此指标是保守的直接农业交付计数。它不改变物品总量或经济账本。
- `SetFarmPlotPolicyCommand` 支持自动、菠菜、羽衣甘蓝、羊生菜、休耕；变更当前植株的方针只在下一次采收后结束原作物。`SetGrowingBedHeatPolicyCommand` 支持关闭、普通、优先，优先只改变菜床之间的工作排序。命令在 tick 边界应用，有效变更标记辅助成绩，无效目标／枚举拒绝；同值不重复标记干预。
- `FarmPlotSnapshot` 与 `GrowingBedSnapshot` 提供不可变的方针、作物、采收次数、生长余量对应进度、土温、燃料、覆雪、维护及停工原因。`GameSession.PendingFarmingPolicies` 是独立只读订单快照，读档后仍可显示待执行。沿用现有右侧物资详情，农田选择将种植设置置顶；暂停不直接改变模拟。
- `WinterFarmingAtlas.png` 独立包含三类作物的生长／枯损、菜床围护／雪盖、炉火以及种子包共 48 张切片。生成菜单为 **Tools → My AI World → Art → Generate Winter Farming Art**；保留旧图集及其切片、`.meta`，不重建 Bootstrap。读档统一重建绑定菜床与作物视图。
- `HabitatPatchState` 的残果、种实、地下根系、灌木嫩枝与树木枝皮是现有植被生物量中的有限可食份额。觅食查询与进食共享同一物种／季节／积雪规则；消耗份额同时扣所属植被，采伐／采集／自然衰退也扣相应份额。冬季灌木增加不能变成新鲜浆果，野外食物节点只能转换真实残果。食物与水的生态账本保持独立守恒。
- 野兔利用残存草本、嫩枝与枝皮；鹿利用灌木枝芽；野猪利用根茎、种实、残果并食腐；田鼠利用雪下草根和种实；狐狼捕食兼食腐肉；渡鸦利用腐肉与残留种实。深雪统一影响日常移动和遭遇逃跑，增加地表活动能耗，田鼠有雪下保温优势；暴雪时寻找具有实际植被庇护的栖地。完好菜床阻止兽害，NPC 预留不能保护露地作物。
- `WinterEcologyRules` 为本地和区域动物提供同一繁殖窗口：鹿秋配春产、野猪冬配春产、狐狼冬末配种，兔／渡鸦以春夏为主，田鼠仅在有食物、足够雪被和庇护时冬繁。鹿／野猪孕育 70／35 游戏日，狐／狼 16／19 日，兔 9 日，渡鸦 6 日，田鼠 3 日；出生仍从母体真实储备转移生物量并受可食资源承载限制。迁徙、尸体、捕食与狩猎保持真实实体和唯一结算。
- 存档外壳／世界快照 v7，生态块 v3，哈希 v9，回放摘要 v8；战斗块保持 v3。默认目录为 `MyAiWorld/saves-winter-farming-v7`，旧目录原样保留并明确拒绝旧档。作物、床体热量／燃料、方针、采收与生长余量、可食份额进入世界哈希；待执行命令保存在会话负载中并受完整负载 SHA-256 校验，应用后进入 tick 哈希，不为暂停排队提前修改世界。

本轮验证和仍有的限制见 [冬季种植与生态验收](Progress/Winter-Farming-2026-10-25.md)。
